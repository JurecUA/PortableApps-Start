# PortableApps Start — предварительный аудит PortableApps Platform 30.4

Дата проверки: 12 ноября 2026 г.

## Объём и достоверность

Цель аудита — подготовить безопасный план форка с новой оболочкой, сохранив PortableApps Platform и её пользовательские данные. Официальная страница SourceForge подтверждает наличие отдельных архивов исходников версии 30.4 для Platform, Start и Updater. Также на странице указан установщик Platform 30.5, поэтому 30.4 — выбранная пользователем база, но не самая новая опубликованная версия на момент проверки.

Архив Platform 30.4 найден и его SHA-256 на SourceForge указан как `92d6a138540c3059691853ab61aaa36092060b3ccefb1d9e09f738aef43b0982`. В этой рабочей среде загрузка SourceForge вместо архива возвращает HTML-страницу; получить и распаковать исходники не удалось. Репозиторий GitHub `PortableApps/Platform` доступен, но его публичная страница показывает только два коммита и папку `.github`, поэтому он не заменяет архив исходного кода.

**Вывод:** это предварительный, а не завершённый кодовый аудит. Реализацию функций, зависимости, конфигурационные форматы, команды сборки и точную карту файлов нужно подтвердить по распакованным официальным архивам до изменений кода. В частности, нельзя считать перечисленные ниже пункты подтверждёнными только потому, что они упомянуты в спецификации.

## Проверенные источники

- SourceForge: каталог исходников Platform 30.4 показывает `PortableAppsPlatformSource30.4.7z`, `PortableAppsStartSource30.4.7z` и `PortableAppsUpdaterSource30.4.7z`.
- SourceForge: страница архива Platform указывает SHA-256 и описание встроенной установки/обновления приложений.
- GitHub: [PortableApps/Platform](https://github.com/PortableApps/Platform) — публичная страница репозитория; по видимой странице это не полный исходный проект.
- Страница поддержки PortableApps не загрузилась в инструменте просмотра, содержимое не использовалось как доказательство.
- Официальный [журнал изменений платформы](https://portableapps.com/platform/changelog) сообщает, что в выпуске 30.3 компилятор обновлён до Delphi 13.1. Это позволяет предварительно определить основную версию компилятора для базы 30.4; конкретную редакцию и дополнительные компоненты ещё нужно сверить с исходными проектами.

## Известная структура комплекта исходников

Официальный каталог делит исходный комплект как минимум на три самостоятельных архива:

| Компонент | Архив 30.4 | Роль по названию и каталогу; требует подтверждения кодом |
|---|---|---|
| Platform | `PortableAppsPlatformSource30.4.7z` | Основная платформа и пользовательский интерфейс |
| Start | `PortableAppsStartSource30.4.7z` | Компонент запуска Platform |
| Updater | `PortableAppsUpdaterSource30.4.7z` | Обновляющий компонент |

Это ещё не карта зависимостей. Следующий аудит должен распаковать каждый архив, проследить проекты и вызовы между компонентами и выявить инструменты сборки по файлам проекта и скриптам.

## Функции, заявленные спецификацией, для проверки в коде

Для каждой функции сначала найти реальную точку входа и сохранённый формат состояния:

- обнаружение установленных PortableApps и построение списка приложений;
- запуск, параметры запуска и запуск с повышенными правами;
- категории, избранное/закрепление, порядок, скрытие и контекстные команды;
- автозапуск выбранных приложений;
- горячая клавиша, трей, единственный экземпляр и скрытие после запуска;
- установка/проверка обновлений приложений и обновление самой платформы;
- архивирование и восстановление;
- настройки, локализация, темы, DPI и обработка нескольких экранов.

До проверки кода нельзя гарантировать сохранение какой-либо из этих функций новой оболочкой.

## Предварительные архитектурные рекомендации

1. Сохранить процесс и логику Platform 30.4 как основу. Визуальное окно выделять отдельным компонентом только если существующая архитектура это позволяет без переписывания механизмов запуска и данных.
2. Сначала составить карту сообщений/событий между Platform, Start и Updater. Не удалять код updater-а: отдельно отключить только проверку обновлений самой платформы, если это возможно без изменения обновлений приложений.
3. Для закреплений, пользовательских категорий и порядка сначала проверить, можно ли расширить текущие настройки без изменения форматов приложений и миграции профиля. Новые значения хранить в отдельном версионируемом пользовательском файле, если формат платформы не подходит.
4. Не внедрять тяжёлый UI-фреймворк до выяснения стека 30.4. Рассмотреть штатные Win32/DPI и графические средства уже используемого стека.
5. Иконка PortableApps Start: компактный знак из четырёх квадратов меню «Пуск» внутри контура переносного USB-накопителя; один квадрат выделен фирменным синим. Сделать векторный мастер и набор `.ico` размеров, проверить читаемость в трее и на светлом/тёмном фоне. Это концепция, не готовый ресурс.

## Что требуется для завершения аудита

- Получить официальные архивы Platform, Start и Updater версии 30.4, проверить SHA-256 и распаковать их.
- Снять полный перечень исходников, проектов, библиотек и ресурсов.
- Зафиксировать проверенные файлы и функции с путями и точками входа.
- Собрать оригинальную версию по инструкциям проекта, чтобы иметь контрольную базу.
